# Wallify v1.7.2 更新日志补充

## 本次修复

本版本重点修复了启动页 Logo 显示异常和点击上传按钮后出现白屏的问题，提升首次启动与核心发布流程的稳定性。

### 修复启动页 Logo 闪烁与前置空白

此前应用启动时会先显示一段没有 Logo 的空白画面，随后 Logo 快速闪现并立即消失，导致用户难以辨认品牌标识。问题主要与原生启动屏过早隐藏，以及应用层 Logo 图片尚未完成首帧渲染有关。

本次调整将原生启动屏改为深灰背景配 Wallify 官方横版 Logo，并在应用首帧完成布局后再隐藏原生启动屏。同时，应用内 Logo 过渡改为本地图片渲染，Logo 保持约 1.6 秒的清晰展示时间，再以 0.3 秒淡出，减少空白、闪现和画面跳变。

### 修复点击上传按钮后白屏

此前底部导航中间的上传按钮会进入 `(tabs)/upload.tsx` 占位路由，而该页面没有实际内容，因此点击后只显示空白页面。与此同时，上传按钮的自定义导航配置与 Expo Router 的 `href` 配置存在冲突，可能进一步触发全局路由渲染错误。

本次将真实上传表单迁移到独立的 `/upload-wallpaper` 页面，并统一修正底部导航、设置页账户卡片和登录成功后的回跳地址。上传页面现在可以正常显示登录状态、相册选择、标题、分类、描述、标签和发布操作；未登录用户也会获得明确的登录入口，而不是进入空白页。

## 验证结果

本次修复已完成 TypeScript 类型检查、12 项自动化测试（另有 1 项按现有配置跳过）、Expo 配置解析，以及主页和独立上传页面的移动端预览验证。需要注意的是，原生启动屏的最终表现必须安装重新构建的 Android APK 后在真实设备上确认；预览环境无法完全模拟 Android 12 独立应用的启动屏行为。

## 用户可见变化

| 功能 | 修复前 | 修复后 |
| --- | --- | --- |
| 启动页 | Logo 前有空白，Logo 一闪而过 | 深灰背景立即出现，Logo 清晰展示后平滑淡出 |
| 底部上传按钮 | 点击后进入白屏占位页 | 进入完整的原生上传页面 |
| 设置页上传入口 | 可能进入旧 `/upload` 路径 | 统一进入 `/upload-wallpaper` |
| 登录后回跳 | 上传流程回跳地址不统一 | 登录成功后返回上传页面 |

> 建议发布流程：通过 GitHub Actions 重新构建并安装新的 Android APK，再在真实设备上分别测试冷启动、热启动、底部上传按钮和设置页上传入口。
